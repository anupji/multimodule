What happens when 20 tasks are submitted?


When 20 tasks are submitted to the specified , the tasks will be processed based on the configuration of the thread pool. Let's see what will happen step by step given its configuration: `ThreadPoolExecutor`
1. **ThreadPoolExecutor Configuration**:
    - `corePoolSize = 2`: The pool will always try to have at least 2 threads active.
    - `maximumPoolSize = 4`: The pool can have up to 4 threads in total.
    - `keepAliveTime = 10 seconds`: If a thread beyond the is idle for more than 10 seconds, it will be terminated. `corePoolSize`
    - `BlockingQueue of size 10`: The queue can hold up to 10 tasks before rejecting additional tasks.

2. **What Happens When 20 Tasks Are Submitted**:
    - **First 2 tasks**: The will immediately execute the first 2 tasks with the 2 core threads. `ThreadPoolExecutor`
    - **Next 10 tasks (from 3 to 12)**: These will be placed in the **blocking queue**, which can hold up to 10 tasks.
    - **Tasks 13 to 14**: Since the queue is full, the thread pool will create up to 2 additional threads (to reach the `maximumPoolSize` of 4) to handle these tasks, executing them immediately.
    - **Tasks 15 to 20**: At this point:
        - The 2 core threads and 2 additional threads (max pool size) are all busy executing tasks.
        - The queue is full with 10 tasks waiting to be executed.
        - New tasks (tasks 15 to 20) cannot be accepted.
        - The thread pool will invoke its **rejection policy** for these tasks.

3. **Rejection Policy**: The default rejection policy of is , which throws a for any task that cannot be submitted. If you have not specified a custom rejection handler, the submission of tasks 15 to 20 will result in . `ThreadPoolExecutor``AbortPolicy``RejectedExecutionException``RejectedExecutionException`

### Summary of Task Handling
1. Tasks **1 to 2**: Executed by the 2 core threads immediately.
2. Tasks **3 to 12**: Queued in the blocking queue.
3. Tasks **13 to 14**: Handled by 2 additional threads, reaching the maximum pool size of 4.
4. Tasks **15 to 20**: Rejected with (if no custom rejection handler is provided). `RejectedExecutionException`

==================== LOAD BALANCER vs API GATEWAY ====================

LOAD BALANCER (Like a Floor Manager)
----------------------------------------------------------------------
A Load Balancer primarily distributes traffic across multiple servers.

Responsibilities:
1. Does NOT know whether the request is from a real customer or a bot.
2. Manages only traffic distribution.
3. Focuses on delivery, not application-level security.

Example Architecture:

                         Request
                            |
                            v
                   +----------------+
                   | Load Balancer  |
                   +----------------+
                     /    |    |   \
                    /     |    |    \
               Server1 Server2 Server3 Server4


Examples:
- AWS ALB (Application Load Balancer)
- NGINX
- Kong

Layer 7 Load Balancer (Smart LB):
- Can handle path-based routing
- Basic filtering
- Host-based routing

Example:
- /api/users  -> User Service
- /api/orders -> Order Service

When to Use Only a Load Balancer:
- Internal traffic
- Early-stage applications
- Limited public APIs
- Simple traffic distribution


======================================================================

API GATEWAY
----------------------------------------------------------------------
API Gateway is a smarter version of a reverse proxy.

Acts as:
- Single Entry Point
  Example: api.tadaka.com

Main Responsibilities:
- Authentication
- Authorization
- Rate Limiting
- Routing

===========**not null** and **not empty**============


To handle the common scenario where every object needs to be checked to ensure it is **not null** and **not empty** before performing any operations on it, we can adopt better practices provided by modern Java features and design principles. Below are some strategies to simplify and improve such null and emptiness checks in Java:

---

### 1. **Use Utility Methods for Common Checks**
Create a utility class with reusable methods to handle null and empty conditions for specific object types (e.g., Collections, Strings, Optionals, etc.).

```java
import java.util.Collection;
import java.util.Map;

public class ObjectUtils {

    // Checks if an object is not null and applicable for operations
    public static boolean isUsable(Object obj) {
        return obj != null;
    }

    // Checks if a string is neither null nor empty
    public static boolean isUsable(String str) {
        return str != null && !str.isEmpty();
    }

    // Checks if a collection is neither null nor empty
    public static boolean isUsable(Collection<?> collection) {
        return collection != null && !collection.isEmpty();
    }

    // Checks if a map is neither null nor empty
    public static boolean isUsable(Map<?, ?> map) {
        return map != null && !map.isEmpty();
    }
}
```


### **Usage**:
```java
if (ObjectUtils.isUsable(myMap)) {
    // Perform operations on map
}

if (ObjectUtils.isUsable(myCollection)) {
    // Perform operations on collection
}

if (ObjectUtils.isUsable(myString)) {
    // Perform operations on string
}
```


### Benefits:
- Reusability: Wrap repeated patterns into one common place.
- Improved readability: Code becomes more descriptive and concise.
- Easy to update logic globally if needed.

---

### 2. **Use `Optional` for Better Null Handling**
`Optional` (available since Java 8) can eliminate the need for manual null checks and provide a safer mechanism for handling potentially null objects. It can also wrap empty checks for collections or strings.

#### Example of Optional Usage:
```java
import java.util.Optional;

public class OptionalUtils {

    // Performs an action only if the optional value is present and meets criteria (not empty in case of string/collection)
    public static void performIfValid(Optional<?> optional, Runnable action) {
        optional.ifPresent(value -> {
            if (!(value instanceof String str && str.isEmpty())
                && !(value instanceof Collection<?> collection && collection.isEmpty())
                && !(value instanceof Map<?, ?> map && map.isEmpty())) {
                action.run(); // Perform action only when valid
            }
        });
    }
}
```


#### **Usage**:
```java
Optional<String> optionalString = Optional.ofNullable(myString);
OptionalUtils.performIfValid(optionalString, () -> System.out.println("Valid non-empty string found: " + myString));

Optional<Map<String, String>> optionalMap = Optional.ofNullable(myMap);
OptionalUtils.performIfValid(optionalMap, () -> System.out.println("Valid non-empty map found."));
```


### Benefits:
- Encapsulates null and empty checks into a single safe usage API.
- Reduces explicit null-check boilerplate and ensures developer safety.

---

### 3. **Leverage Java 17 Sealed Classes for Specific Use Cases**
If you have specific objects that need checks for emptiness (e.g., Strings, Collections, Maps), sealed class hierarchies can ensure compile-time safety for these checks.

#### Example:
```java
public sealed interface Validatable permits ValidatableString, ValidatableCollection {
    boolean isValid();
}

public final class ValidatableString implements Validatable {
    private final String value;

    public ValidatableString(String value) {
        this.value = value;
    }

    @Override
    public boolean isValid() {
        return value != null && !value.isEmpty();
    }
}

public final class ValidatableCollection implements Validatable {
    private final Collection<?> collection;

    public ValidatableCollection(Collection<?> collection) {
        this.collection = collection;
    }

    @Override
    public boolean isValid() {
        return collection != null && !collection.isEmpty();
    }
}
```


#### **Usage**:
```java
Validatable stringValidator = new ValidatableString(myString);
if (stringValidator.isValid()) {
    System.out.println("Valid string: " + myString);
}

Validatable collectionValidator = new ValidatableCollection(myCollection);
if (collectionValidator.isValid()) {
    System.out.println("Valid collection: " + myCollection);
}
```


### Benefits:
- Type-safe mechanism to validate objects.
- The sealed class approach enforces strict rules on what types can be considered "Validatable."

---

### 4. **Combine `Optional` and Stream API**
For working with collections or performing operations only when objects are valid, combining `Optional` and streams can create concise logic.

#### Example:
```java
import java.util.Collection;
import java.util.Optional;

public class StreamUtils {

    // Process a collection only if it's not null and not empty
    public static void processIfUsable(Collection<?> collection, Runnable action) {
        Optional.ofNullable(collection)
                .filter(c -> !c.isEmpty())
                .ifPresent(c -> action.run());
    }
}
```


#### **Usage**:
```java
StreamUtils.processIfUsable(myCollection, () -> {
    myCollection.forEach(System.out::println);
});
```


### Benefits:
- Combines readability improvements of streams with null-check safety.

---

### 5. **Use Java Records for Immutability Checks**
In cases where you need to group objects (e.g., a combination of strings and collections) and ensure they are non-null and valid, make use of **records** introduced in Java 14 for immutability.

#### Example:
```java
public record ValidatableGroup(String string, Collection<?> collection) {
    public boolean isValid() {
        return string != null && !string.isEmpty() 
            && collection != null && !collection.isEmpty();
    }
}
```


#### **Usage**:
```java
var group = new ValidatableGroup(myString, myCollection);
if (group.isValid()) {
    System.out.println("String and collection are valid!");
}
```


### Benefits:
- Simpler declarations with `record`.
- Prevents mutable state issues and keeps validation logic centralized.

---

### General Best Practices:
1. **Adopt Defensive Programming**:
   - Validate object state at the boundaries of your application (e.g., APIs, controllers).
   - Avoid redundant checks deeper into your codebase when already validated at the entry point.

2. **Fail Fast**:
   - Use `Objects.requireNonNull()` for critical fields instead of deferring the validation to business logic.

3. **Lombok for Automatic Handling** (Optional Tool):
   - For common null or empty checks, Lombok’s `@NonNull` or custom annotations can inject validations automatically during compile time.

---

By combining utility methods, `Optional`, sealed class hierarchies, or records, you can simplify null and emptiness checks, improve code safety, and reduce manual boilerplate while adhering to modern Java conventions.

@Configuration
public class CustomMessageSourceConfiguration extends AcceptHeaderLocaleResolver implements WebMvcConfigurer {
    List<Locale> LOCALES = Arrays.asList(new Locale("en"), new Locale("fr"));

    @Override
    public Locale resolveLocale(HttpServletRequest request) {
        String headerLang = request.getHeader("Accept-Language");
        return headerLang == null || headerLang.isEmpty() ? Locale.US : Locale.lookup(Locale.LanguageRange.parse(headerLang), LOCALES);

        messageSource.setBasename("messages");

        messageSource.setUseCodeAsDefaultMessage(true);

1. आवश्यकताओं की पहचान (Requirement Analysis)

===========@Bean and @Component============
Difference between @Bean and @Component? When to use which?

In the context of Spring Framework and Spring Boot, both @Component and @Bean register objects in the Spring IoC container, but they are used in different scenarios.

@Component

@Component is used directly on a class.

Spring automatically detects it during component scanning and creates the bean for you.

@Component
public class EmailService {
    public void send() {
        System.out.println("Sending email");
    }
}
Typical use cases

Use @Component (or specialized stereotypes like @Service, @Repository, @Controller) when:

You own the source code of the class
The class represents application/business logic
You want automatic scanning and registration
The bean creation is straightforward
Related stereotypes

These are specialized versions of @Component:

@Service
@Repository
@Controller
@RestController

They behave like @Component but add semantic meaning.

@Bean

@Bean is used on a method inside a @Configuration class.

The method explicitly creates and returns the object.

@Configuration
public class AppConfig {

    @Bean
    public EmailService emailService() {
        return new EmailService();
    }
}
Typical use cases

Use @Bean when:

You need manual control over object creation
The object requires complex setup
You need constructor arguments/configuration
You are integrating third-party libraries
You cannot modify the class source

Example with third-party class:

@Configuration
public class Config {

    @Bean
    public ObjectMapper objectMapper() {
        ObjectMapper mapper = new ObjectMapper();
        mapper.findAndRegisterModules();
        return mapper;
    }
}

You cannot annotate ObjectMapper with @Component because it belongs to another library.

Core Difference
Aspect	@Component	@Bean
Applied on	Class	Method
Bean creation	Automatic by Spring	Manual by developer
Requires component scanning	Yes	No
Best for	Your own application classes	External/library/complex objects
Flexibility	Less	More
Configuration style	Declarative	Programmatic
Internal Flow

With @Component:

@Component
class A {}

Spring:

Scans package
Finds A
Instantiates automatically

With @Bean:

@Configuration
class Config {
    @Bean
    A a() {
        return new A();
    }
}

Spring:

Creates Config
Calls method a()
Registers returned object
Real-world guideline
Prefer @Component for:
Services
Repositories
Controllers
Most application classes
Prefer @Bean for:
Third-party classes
Custom initialization logic
Multiple bean variants
Conditional/config-driven creation
Common interview answer

A concise way to explain it:

@Component lets Spring automatically create beans through classpath scanning, while @Bean gives the developer explicit control over bean creation through configuration methods.

Example using both together
@Component
public class UserService {
}
@Configuration
public class AppConfig {

    @Bean
    public ObjectMapper objectMapper() {
        return new ObjectMapper();
    }
}

Here:

UserService is app logic → @Component
ObjectMapper is third-party + configurable → @Bean
Rule of thumb
If Spring can safely auto-create it → use @Component
If creation logic matters → use @Bean
As we create @Bean of RestTemplate in Main Application class annotated with @SpringBootApplication right?

Yes — that’s a very common pattern in Spring Boot applications.

Example:

@SpringBootApplication
public class MyApplication {

    public static void main(String[] args) {
        SpringApplication.run(MyApplication.class, args);
    }

    @Bean
    public RestTemplate restTemplate() {
        return new RestTemplate();
    }
}

Then you can inject it anywhere:

@Service
public class UserService {

    @Autowired
    private RestTemplate restTemplate;
}
Why @Bean here instead of @Component?

Because RestTemplate is a class from VMware Spring libraries — you usually don’t modify its source code to add @Component.

Also, you often want custom configuration:

@Bean
public RestTemplate restTemplate() {
    RestTemplate template = new RestTemplate();

    template.setRequestFactory(
        new HttpComponentsClientHttpRequestFactory()
    );

    return template;
}

So @Bean is the correct choice.

Why it works inside @SpringBootApplication

@SpringBootApplication internally includes:

@Configuration
@ComponentScan
@EnableAutoConfiguration

Since it already acts as a @Configuration class, Spring allows @Bean methods inside it.

So this is valid:

@SpringBootApplication
public class App {

    @Bean
    public RestTemplate restTemplate() {
        return new RestTemplate();
    }
}
Better practice in larger projects

For small apps, putting beans in the main class is fine.

For larger applications, people usually separate configuration:

@Configuration
public class AppConfig {

    @Bean
    public RestTemplate restTemplate() {
        return new RestTemplate();
    }
}

This keeps the main application class clean.

Modern note

In newer Spring applications, many developers prefer WebClient over RestTemplate.

RestTemplate is in maintenance mode.

Example:

@Bean
public WebClient webClient() {
    return WebClient.builder().build();
}

       extends JpaRepository<User, Long> {

@Service
public class KafkaProducerService {

    @Autowired
    private KafkaTemplate<String, Object> kafkaTemplate;

    public void publishUser(User user) {

        kafkaTemplate.send(
            "user_details-topic",
            user
        );
    }

@Service
public class UserService {

    @Autowired
    private UserRepository userRepository;

    @Autowired
    private KafkaProducerService producerService;

    public void sendUserToKafka(Long id) {

        User user = userRepository.findById(id)
                                  .orElseThrow();

        producerService.publishUser(user);
    }
}

==========SpringBootApplication===========
What is the use of @SpringBootApplication how it works, what all annotation it includes?

@SpringBootApplication is the main convenience annotation in Spring Boot applications.
It marks the main class of a Spring Boot app and combines multiple important Spring annotations into one.

Example:

@SpringBootApplication
public class MyApplication {

    public static void main(String[] args) {
        SpringApplication.run(MyApplication.class, args);
    }
}
What is the use of @SpringBootApplication?

It is used to:

Mark the class as the starting point of a Spring Boot application
Enable auto-configuration
Enable component scanning
Allow defining Spring beans
Simplify Spring configuration

Without it, you would need to manually add several annotations separately.

What annotations does it include?

@SpringBootApplication is actually a combination of 3 annotations:

@SpringBootConfiguration
@EnableAutoConfiguration
@ComponentScan

Let’s understand each one.

1. @SpringBootConfiguration

This is a specialized version of @Configuration.

It tells Spring:

“This class contains bean definitions and configuration.”

Equivalent to:

@Configuration

Example:

@Bean
public MyService myService() {
    return new MyService();
}

Spring creates and manages this bean in the IoC container.

2. @EnableAutoConfiguration

This is the most powerful feature of Spring Boot.

It tells Spring Boot:

“Automatically configure the application based on dependencies present in the classpath.”

Example:

If you add:

spring-boot-starter-web

Spring Boot automatically configures:

Tomcat server
DispatcherServlet
Jackson JSON support
Spring MVC setup

No XML configuration needed.

Another example:

If Spring Boot detects:

spring-boot-starter-data-jpa

it auto-configures:

DataSource
Hibernate
EntityManager
Transaction manager
How Auto Configuration Works Internally

Spring Boot checks:

Dependencies in classpath
Existing beans
Application properties

Then it loads matching configuration classes.

Internally it uses:

@Conditional

annotations like:

@ConditionalOnClass
@ConditionalOnMissingBean
@ConditionalOnProperty

Example:

@ConditionalOnClass(DataSource.class)

This configuration activates only if DataSource exists.

3. @ComponentScan

This tells Spring:

“Scan packages and register Spring components automatically.”

Spring scans for:

@Component
@Service
@Repository
@Controller
@RestController

Example:

@Service
public class UserService {
}

Spring automatically creates the bean.

How package scanning works

Suppose:

package com.example.app;

and your main class is:

package com.example.app;

@SpringBootApplication
public class MyApplication {
}

Spring scans:

com.example.app
com.example.app.*

So all subpackages are scanned automatically.

Internal Structure of @SpringBootApplication

Simplified version:

@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Documented
@Inherited

@SpringBootConfiguration
@EnableAutoConfiguration
@ComponentScan
public @interface SpringBootApplication {
}
What happens when application starts?

When this runs:

SpringApplication.run(MyApplication.class, args);

Spring Boot:

Creates Spring Application Context
Starts embedded server (Tomcat/Jetty)
Performs component scan
Creates beans
Applies auto-configuration
Loads properties
Starts the application
Example Flow

Suppose you add:

spring-boot-starter-web

and create:

@RestController
public class HelloController {

    @GetMapping("/hello")
    public String hello() {
        return "Hello";
    }
}

What happens:

@ComponentScan finds controller
@EnableAutoConfiguration configures Spring MVC + Tomcat
@SpringBootConfiguration allows bean definitions
Embedded Tomcat starts
Endpoint becomes available
Can we replace @SpringBootApplication manually?

Yes.

Instead of:

@SpringBootApplication

you can write:

@Configuration
@EnableAutoConfiguration
@ComponentScan

Behavior is almost the same.

Because @ComponentScan scans current package and subpackages.

Best practice:

Place main class at top/root package.

Q2: Can we exclude auto-configuration?

Yes.

Example:

@SpringBootApplication(
    exclude = DataSourceAutoConfiguration.class
)

Useful when you don’t want DB configuration.

Q3: Difference between @Configuration and @SpringBootConfiguration?

@SpringBootConfiguration is basically:

@Configuration

with Spring Boot-specific semantics.

# Very Important Interview Questions

## 23. Difference between WHERE and HAVING

* `WHERE` filters rows before grouping
* `HAVING` filters groups after `GROUP BY`

Example:

```sql
SELECT customer_id, SUM(amount)
FROM Orders
WHERE amount > 200
GROUP BY customer_id
HAVING SUM(amount) > 700;
```

---

## 24. Difference between INNER JOIN and LEFT JOIN

* `INNER JOIN` → matching rows only
* `LEFT JOIN` → all left table rows + matching rows

The CAP theorem is a principle in distributed computing that says a distributed system can guarantee only **two out of these three properties at the same time**:
1. **Consistency (C)**
   Every user sees the same data at the same time.
   After a write, all reads return the latest value.
2. **Availability (A)**
   Every request gets a response, even if some servers are down.
3. **Partition Tolerance (P)**
   The system continues working even when network communication between nodes fails.

The theorem states:
> During a network partition, a distributed system must choose between **Consistency** and **Availability**.
---
### Visual idea

```
        CAP Theorem

           Consistency
               /\
              /  \
             /    \
            /      \
 Availability ---- Partition Tolerance
```

In real distributed systems, **Partition Tolerance is usually mandatory**, because network failures can always happen.
So systems typically choose between:
* **CP systems** → Consistency + Partition Tolerance
* **AP systems** → Availability + Partition Tolerance
---
### Examples
#### CP Systems
Prioritize correct and consistent data.
Examples:
* MongoDB (with strong consistency settings)
* HBase
* ZooKeeper

Behavior:
* May reject requests during network failures.
* Data remains accurate.
---
#### AP Systems

Prioritize always responding.

Examples:

* Cassandra
* DynamoDB

Behavior:

* System keeps serving requests.
* Different nodes may temporarily show different data.

---

### Simple analogy

Imagine bank servers in two cities lose internet connection:

* If both continue independently → users may see different balances (**Availability over Consistency**).
* If one stops transactions until reconnection → data stays correct but service may be unavailable (**Consistency over Availability**).

---

### Important note

Many modern systems use **eventual consistency**, meaning:

* Data may be temporarily inconsistent,
* But all nodes eventually become consistent.

This is common in large-scale cloud systems.

How to approach to a HLD question,

1) Requirements
2) Core Entities
3) API or Interface
4) Data flow [Optional]
5) High Level Design
6) Deep dives

Requirements: Talk about Functional and Non-Functional requirements
Functional: These are your "Users/Clients should be able to..." statements.
Non-Functional: These are statements about the system qualities that are important to your users. These can be phrased as "The system should be able to..." or "The system should be..." statements.

Core Entities: Identify and list the core entities of your system. This helps you to define terms, understand the data central to your design, and gives you a foundation to build on. These are the core entities that your API will exchange and that your system will persist in a Data Model.

API or Interface: Define the contract between your system and its users. Oftentimes, especially for full product style interviews, this maps directly to the functional requirements you've already identified (but not always!). You will use this contract to guide your high-level design and to ensure that you're meeting the requirements you've identified.

Data flow: For some backend systems, especially data-processing systems, it can be helpful to describe the high level sequence of actions or processes that the system performs on the inputs to produce the desired outputs. If your system doesn't involve a long sequence of actions, skip this!

High Level Design: Now that you have a clear understanding of the requirements, entities, and API of your system, you can start to design the high-level architecture. This consists of drawing boxes and arrows to represent the different components of your system and how they interact. Components are basic building blocks like servers, databases, caches, etc

Don't over think this! Your primary goal is to design an architecture that satisfies the API you've designed and, thus, the requirements you've identified

Deep dives: Now that you have a high-level design in place you're going to harden your design by:
-> Ensuring it meets all of your non-functional requirements
-> Addressing edge cases
-> Identifying and addressing issues and bottlenecks
-> Improving the design based on probes from your interviewer.

CREATE TABLE customers (
  customer_id INT PRIMARY KEY, 
  name VARCHAR(100), 
  region VARCHAR(50), 
  created_at DATETIME
);

CREATE TABLE orders order_id
  order_id INT PRIMARY KEY, 
  customer_id INT, 
  status ENUM(
    'PENDING', 'CONFIRMED', 'SHIPPED', 
    'CANCELLED', 'RETURNED'
  ), 
  amount DECIMAL(10, 2), 
  order_date DATETIME, 
  FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
);

CREATE TABLE order_items (
  item_id INT PRIMARY KEY, 
  order_id INT, 
  product_id INT, 
  quantity INT, 
  unit_price DECIMAL(10, 2), 
  FOREIGN KEY (order_id) REFERENCES orders(order_id)
);

CREATE TABLE products (
  product_id INT PRIMARY KEY, 
  name VARCHAR(100), 
  category VARCHAR(50), 
  cost_price DECIMAL(10, 2)
);

CREATE TABLE payments (
  payment_id INT PRIMARY KEY, 
  order_id INT, 
  paid_at DATETIME, 
  method ENUM(
    'UPI', 'CARD', 'NETBANKING', 'COD'
  ), 
  status ENUM('SUCCESS', 'FAILED', 'REFUNDED'), 
  FOREIGN KEY (order_id) REFERENCES orders(order_id)
);

@Table(name  = "employee")
@Entity(name = "employee")
public class Employee {

    @Id
    private Long id;

    @Column(nullable = false)
    private String name;

    @Column(nullable = false, unique = true)
    private String email;

    @Column
    private String department;



@Service
@RequiredArgsConstructor
public class EmployeeService {

    private EmployeeRepository employeeRepository;

    // 1 & 2 - Create table and Insert records
    public Employee saveEmployee(Employee employee) {
        return employeeRepository.save(employee);
    }

    // 3 - Read all records
    public List<Employee> getAllEmployees() {
        return employeeRepository.findAll();
    }

    // Read single record by ID
    public Optional<Employee> getEmployeeById(Long id) {
        return employeeRepository.findById(id);
    }

    // 4 - Update record
    public Employee updateEmployee(Long id, Employee updatedEmployee) {

        Employee employee = employeeRepository.findById(id)
                .orElseThrow(() -> new RuntimeException("Employee not found"));

        employee.setName(updatedEmployee.getName());
        employee.setEmail(updatedEmployee.getEmail());
        employee.setDepartment(updatedEmployee.getDepartment());

        return employeeRepository.save(employee);
    }

    // 5 - Delete record
    public String deleteEmployee(Long id) {

        Employee employee = employeeRepository.findById(id)
                .orElseThrow(() -> new RuntimeException("Employee not found"));

        employeeRepository.delete(employee);

        return "Employee deleted successfully";
    }
}

public class MinDeletionsToMakeStringBalanced {
    
    public int solution(String s) {
        int openCount = 0;
        int deletions = 0;

        for (char c : s.toCharArray()) {
            if (c == '(') {
                openCount++;
            } else if (c == ')') {
                if (openCount > 0) {
                    openCount--;
                } else {
                    deletions++;
                }
            }
        }

        // Remaining opening brackets need to be deleted
        deletions += openCount;

        return deletions;
    }

    public static void main(String[] args) {
        String s = "))((";
        System.out.println("Minimum deletions required: " + minDeletionsToBalance(s));
    }
}

public class FormatString {
    
    public static String obtainFormatString(String s) {
        int countA = 0, countB = 0;
        
        for (char c : s.toCharArray()) {
            if (c == 'A') {
                countA++;
            } else if (c == 'B') {
                countB++;
            }
        }
        
        StringBuilder result = new StringBuilder();
        
        if (countA > countB) {
            for (int i = 0; i < countB; i++) {
                result.append('A');
            }
            for (int i = 0; i < countB; i++) {
                result.append('B');
            }
        } else {
            for (int i = 0; i < countA; i++) {
                result.append('A');
            }
        }

        return result.toString();
    }

    public static void main(String[] args) {
        String s = "AABBBAAAB"; // Example input string
        String formattedString = obtainFormatString(s);
        System.out.println("Formatted string: " + formattedString);
    }
}






public class MaximumBananaMove {
    
    public static int maxBananaMove(String s) {
        // Count occurrences of each letter
        int[] count = new int[26];
        for (char c : s.toCharArray()) {
            count[c - 'A']++;
        }

        // Calculate how many times "BANANA" can be formed
        int maxMoves = Integer.MAX_VALUE;
        maxMoves = Math.min(maxMoves, count['B' - 'A']); // 'B' appears only once in "BANANA"
        maxMoves = Math.min(maxMoves, count['A' - 'A'] / 3); // 'A' appears three times in "BANANA"
        maxMoves = Math.min(maxMoves, count['N' - 'A'] / 2); // 'N' appears twice in "BANANA"
        
        return maxMoves;
    }

    public static void main(String[] args) {
        String s = "BANANAS";
        System.out.println("Maximum number of times the move can be applied: " + maxBananaMove(s));
    }

public class StringOperations {
    
    public String solution(String s, String t) {
        int n = s.length();
        int m = t.length();

        if (n == m) {
            if (s.equals(t)) {
                return "EQUAL";
            } else if (isInsert(s, t)) {
                return "INSERT";
            } else if (isRemove(s, t)) {
                return "REMOVE";
            } else if (isSwap(s, t)) {
                return "SWAP";
            }
        } else if (n + 1 == m) {
            if (isInsert(s, t)) {
                return "INSERT";
            }
        } else if (n - 1 == m) {
            if (isRemove(s, t)) {
                return "REMOVE";
            }
        }

        return "IMPOSSIBLE";
    }

    private boolean isInsert(String s, String t) {
        int i = 0, j = 0;

        while (i < s.length() && j < t.length()) {
            if (s.charAt(i) != t.charAt(j)) {
                if (i != j) return false;
                j++;
            } else {
                i++;
                j++;
            }
        }

        return true;
    }

    private  boolean isRemove(String s, String t) {
        return isInsert(t, s);
    }

    private  boolean isSwap(String s, String t) {
        int firstDiff = -1, secondDiff = -1;

        for (int i = 0; i < s.length(); i++) {
            if (s.charAt(i) != t.charAt(i)) {
                if (firstDiff == -1) {
                    firstDiff = i;
                } else if (secondDiff == -1) {
                    secondDiff = i;
                } else {
                    return false;
                }
            }
        }

        return (firstDiff != -1 && secondDiff != -1 && 
                s.charAt(firstDiff) == t.charAt(secondDiff) && 
                s.charAt(secondDiff) == t.charAt(firstDiff));
    }

    public static void main(String[] args) {
        String s = "abcd";
        String t1 = "abdc"; // SWAP
        String t2 = "abcde"; // INSERT
        String t3 = "abc"; // REMOVE
        String t4 = "abcdf"; // IMPOSSIBLE

        System.out.println(stringOperation(s, t1)); // SWAP
        System.out.println(stringOperation(s, t2)); // INSERT
        System.out.println(stringOperation(s, t3)); // REMOVE
        System.out.println(stringOperation(s, t4)); // IMPOSSIBLE
    }
}

    // Constructor
    public MethodReferenceExample() {
        System.out.println("Constructor called");
    }

    // Another method
    public void method() {
        System.out.println("Method called");
    }
}

                 .forEach(System.out::println); // Prints numbers from 1 to 9

                 .forEach(System.out::println); // Prints even numbers from 2 to 8

        // Using filter to select elements

                          .sum();

    public Authentication authenticate(Authentication authentication) throws AuthenticationException {
        String username = authentication.getName();
        String password = authentication.getCredentials().toString();

        UserDetails userDetails = userDetailsService.loadUserByUsername(username);

        // Perform custom authentication logic here
        // For example, compare the provided password with the one stored in the UserDetails object
        if (password.equals(userDetails.getPassword())) {
            return new UsernamePasswordAuthenticationToken(username, password, userDetails.getAuthorities());

        }
    }

        return authentication.equals(UsernamePasswordAuthenticationToken.class);
    }
}

import java.security.Key;
import java.util.Base64;
import java.util.Properties;

import javax.crypto.Cipher;
import javax.crypto.spec.SecretKeySpec;
import jakarta.persistence.AttributeConverter;

import org.apache.commons.lang3.StringUtils;
import org.springframework.stereotype.Component;

import lombok.extern.slf4j.Slf4j;

@Slf4j
@Component
public class StringCryptoConverter implements AttributeConverter<String, String> {

	private static String ALGORITHM = null;
	private static byte[] KEY = null;
	public static final String algorithm_property_key = "encryption.algorithm";
	public static final String secret_property_key = "encryption.key";
	public static final Properties properties = new Properties();
	static {
		try {
			properties.load(StringCryptoConverter.class.getClassLoader().getResourceAsStream("encryption.properties"));
		} catch (Exception e) {
			log.error("Exception while reading config {} ",e.getMessage());
			System.exit(-1);
		}
		ALGORITHM = (String) properties.get(algorithm_property_key);
		KEY = ((String) properties.get(secret_property_key)).getBytes();
	}

	@Override
	public String convertToDatabaseColumn(String arg0) {
		if (StringUtils.isBlank(arg0))
			return null;
		Key key = new SecretKeySpec(KEY, "AES");
		try {
			Cipher c = Cipher.getInstance(ALGORITHM);
			c.init(Cipher.ENCRYPT_MODE, key);
			String encryptedData = Base64.getEncoder().encodeToString((c.doFinal(arg0.getBytes())));
			return encryptedData;
		} catch (Exception e) {
			log.error("Error occurred while encrypting input value", e);
			throw new RuntimeException(e);
		}
	}

	@Override
	public String convertToEntityAttribute(String arg0) {
		if (StringUtils.isBlank(arg0))
			return null;
		Key key = new SecretKeySpec(KEY, "AES");
		try {
			Cipher c = Cipher.getInstance(ALGORITHM);
			c.init(Cipher.DECRYPT_MODE, key);
			String decruptedData = new String(c.doFinal(Base64.getDecoder().decode(arg0)));
			return decruptedData;
		} catch (Exception e) {
			log.error("Error occurred while decrypting input value", e);
			return "";
		}
	}

}
